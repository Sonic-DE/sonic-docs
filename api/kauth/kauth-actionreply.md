## Detailed Description {#details}

Helper applications will return this to describe the result of the action.

Callers should access the reply though the [KAuth::ExecuteJob](kauth-executejob.md) job.

## Member Type Documentation {#member-type-documentation}

### enum ActionReply::Error {#Error-enum}

The enumeration of the possible values of [errorCode](kauth-actionreply.md#errorCode)() when [type](kauth-actionreply.md#type)() is ActionReply::KAuthError

| Constant | Value | Description |
| --- | --- | --- |
| `KAuth::ActionReply::NoError` | `0` | No error |
| `KAuth::ActionReply::NoResponderError` | `1` | The helper responder object hasn't been set. This shouldn't happen if you use the KAUTH\_HELPER macro in the helper source |
| `KAuth::ActionReply::NoSuchActionError` | `2` | The action you tried to execute doesn't exist |
| `KAuth::ActionReply::InvalidActionError` | `3` | You tried to execute an invalid action object |
| `KAuth::ActionReply::AuthorizationDeniedError` | `4` | You don't have the authorization to execute the action |
| `KAuth::ActionReply::UserCancelledError` | `5` | Action execution has been cancelled by the user |
| `KAuth::ActionReply::HelperBusyError` | `6` | The helper is busy executing another action (or group of actions). Try later |
| `KAuth::ActionReply::AlreadyStartedError` | `7` | The action was already started and is currently running |
| `KAuth::ActionReply::DBusError` | `8` | An error from D-Bus occurred |
| `KAuth::ActionReply::BackendError` | `9` | The underlying backend reported an error |

### enum ActionReply::Type {#Type-enum}

Enumeration of the different kinds of replies.

| Constant | Value | Description |
| --- | --- | --- |
| `KAuth::ActionReply::KAuthErrorType` | `0` | An error reply generated by the library itself |
| `KAuth::ActionReply::HelperErrorType` | `1` | An error reply generated by the helper |
| `KAuth::ActionReply::SuccessType` | `2` | The action has been completed successfully |

### ActionReply::ActionReply() {#ActionReply}

### ActionReply::ActionReply(KAuth::ActionReply::Type *type*) {#ActionReply-1}

Constructor to directly set the type.

This constructor directly sets the reply type. You shouldn't need to directly call this constructor, because you can use the more convenient predefined replies constants. You also shouldn't create a reply with the KAuthError type because it's reserved for errors coming from the library.

`type` The type of the new reply

### ActionReply::ActionReply(int *errorCode*) {#ActionReply-2}

Constructor that creates a KAuthError reply with a specified error code. Do not use outside the library.

This constructor is for internal use only, since it creates a reply with KAuthError type, which is reserved for errors coming from the library.

`errorCode` The error code of the new reply

### void ActionReply::addData(const QString &*key*, const QVariant &*value*) {#addData}

Convenience method to add some data to the reply.

This method adds the pair `key/value` to the [QVariantMap](https://doc.qt.io/qt-6/qvariant.html#QVariantMap-typedef) used to report back custom data to the application.

Use this method if you don't want to create a new [QVariantMap](https://doc.qt.io/qt-6/qvariant.html#QVariantMap-typedef) only to add a new entry.

`key` The new entry's key `value` The value of the new entry

Returns the data coming from (or that will be sent by) the helper

*See also* [setData](kauth-actionreply.md#setData)()

### int ActionReply::error() const {#error}

Returns the error code of an error reply

The error code returned is one of the values in the [ActionReply::Error](kauth-actionreply.md#Error-enum) enumeration if [type](kauth-actionreply.md#type)() == KAuthError, or is totally application-dependent if [type](kauth-actionreply.md#type)() == HelperError. It also should be zero for successful replies.

Returns the reply error code

*See also* [setError](kauth-actionreply.md#setError)()

### KAuth::ActionReply::Error ActionReply::errorCode() const {#errorCode}

The error code returned is one of the values in the [ActionReply::Error](kauth-actionreply.md#Error-enum) enumeration if [type](kauth-actionreply.md#type)() == KAuthError. Result is only valid if the [type](kauth-actionreply.md#type)() == HelperError

Returns the reply error code

*See also* [setErrorCode](kauth-actionreply.md#setErrorCode)()

### void ActionReply::setError(int *error*) {#setError}

Sets the error code of an error reply

If you're setting the error code in the helper because you need to return an error to the application, please make sure you already have set the type to HelperError, either by calling [setType](kauth-actionreply.md#setType)() or by creating the reply in the right way.

If the type is Success when you call this method, it will become KAuthError

`error` The new reply error code

*See also* [error](kauth-actionreply.md#error)()

### void ActionReply::setType(KAuth::ActionReply::Type *type*) {#setType}

Sets the reply type

Every time you create an action reply, you implicitly set a type. Default constructed replies or [ActionReply::SuccessReply](kauth-actionreply.md#SuccessReply) have [type](kauth-actionreply.md#type)() == Success. [ActionReply::HelperErrorReply](kauth-actionreply.md#HelperErrorReply) has [type](kauth-actionreply.md#type)() == HelperError. Predefined error replies have [type](kauth-actionreply.md#type)() == KAuthError.

This means you rarely need to change the type after the creation, but if you need to, don't set it to KAuthError, because it's reserved for errors coming from the library.

`type` The new reply type

*See also* [type](kauth-actionreply.md#type)()

### bool ActionReply::operator==(const KAuth::ActionReply &*reply*) const {#operator-eq-eq}

Comparison operator

Returns true if the type and the error code of this and `reply` are the same. It *doesn't* compare the data or the error descriptions, so be careful.

The suggested use is to compare a reply against one of the predefined error replies:

```cpp
if(reply == ActionReply::HelperBusyReply) {
   // Do something...
}
```

Note that you can do it also by compare [errorCode](kauth-actionreply.md#errorCode)() with the relative enumeration value.
